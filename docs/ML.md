# Machine-learning pipeline

## What the model does

Flags **abnormal electrical behaviour** per reading: over-consumption, spikes, voltage faults,
low power factor, and power drawn while the relay reports OFF (phantom load / welded relay).

It does **not** decide wastage: "appliance on in a vacant room" is decided by the deterministic
engine. Anomaly results are advisory and never authorize a shutdown (see SAFETY.md).

## Features (`app/ml/features.py`)

| Feature | Definition |
|---|---|
| `power_ratio` | power ÷ rated power (clipped to 10) |
| `delta_ratio` | \|power − previous power\| ÷ rated power (0 if no fresh previous reading) |
| `voltage_dev` | (V − 230) ÷ 230 |
| `power_factor` | P ÷ (V·I) when the load is on and V, I are reported; neutral 0.9 otherwise |
| `relay_mismatch` | 1 if relay reports OFF but power > standby threshold |

Occupancy and time of day are deliberately excluded.

## Data — clearly synthetic

`app/ml/synthetic.py` generates per-appliance sequences from appliance profiles
(`app/simulation/profiles.py`): random-walk power levels, compressor cycling for AC/fridges,
on/off switching, voltage noise. Anomaly **episodes** are injected with labels: spikes last one
reading, other faults persist 1–6 readings. Every model record stores
`data_source = "synthetic (generated by app.ml.synthetic — not real measurements)"`.

## Training and evaluation (`app/ml/model.py`)

* Training: `IsolationForest(n_estimators=200, contamination=0.04, random_state=seed)` on
  16 000 synthetic readings containing ~3 % *unlabelled* anomalies (realistic unsupervised setting).
* Evaluation: an independently seeded synthetic test set (8 000 readings, ~3 % labelled
  anomalies). Reported: precision, recall, F1, ROC-AUC, false-positive rate, confusion matrix,
  recall per anomaly kind.
* Reproducible: same seed ⇒ identical data, model and metrics (tested).
* Trained automatically on first start (`ML_AUTOTRAIN=true`); retrain from the ML page or
  `POST /api/v1/ml/train`; models are versioned in the `ml_models` table and stored with joblib.

### Measured results (seed 42, synthetic held-out test set)

| Metric | Value |
|---|---|
| Precision | 0.701 |
| Recall | 0.867 |
| F1 | 0.775 |
| ROC-AUC | 0.995 |
| False-positive rate | 1.1 % |

Recall by kind: spike 100 %, low power factor 100 %, phantom load 100 %, over-consumption 91 %,
**voltage fault 59 %** (weakest class).

**These numbers only show that the pipeline works on data drawn from the same synthetic
generator. They are not evidence of accuracy on real installations.** Real deployment requires
collecting labelled field data and re-evaluating.

### Design decision recorded during development

Training on normal-only data (novelty detection) was evaluated and **rejected**: Isolation Forest
cannot split on features that are constant in normal data (e.g. `relay_mismatch` is always 0),
so out-of-range anomalies were not isolated and recall fell to 0.24. A first version that injected
only single-reading anomalies also missed *sustained* over-consumption; anomaly episodes fixed
that. Both findings came from tests.

## Inference

Each telemetry reading is scored (`score = −decision_function`, flagged when > 0). The score,
flag and method are stored on the telemetry row. An `anomaly` alert is raised only after
`anomaly_persistence` (default 2) consecutive flagged readings and cleared after 5 normal ones
(hysteresis against one-off noise).

## Fallback

If no model is trained or the artifact fails to load, a transparent rule detector is used
(power > 1.4× rated, step change > 1.5× rated, voltage deviation > 9 %, power factor < 0.6, relay
mismatch). The active method is shown on the dashboard and ML page.
